## SUMMARY
Research for the novalis rewrite covering monorepo layout, i18n, settings governance, mac release/signing, quality process and the empty-branch switch, for BOTH a Rust-core+Tauri variant and a Swift-native variant. WebFetch/WebSearch, the gh CLI and local toolchain probes were all available and used; nothing in the project was modified (probe packages live only in the session scratchpad). VERIFIED baseline of the old novalis: Cargo workspace (3 members, Rust pinned 1.93.0) + pnpm 11 workspace, i18next 26 + react-i18next 17 + i18next-parser 9.4 (now deprecated upstream in favour of i18next-cli 1.73.1) + eslint-plugin-i18next 6.1.4 with locales de/en/es/fr, 16 namespaces and 1,233 keys per locale (406 of them in settings.json alone), a 3-OS CI with cargo-audit/cargo-deny, a tag-driven tauri-action v1.0.0 release that ships UNSIGNED builds, no updater, and a README promise of 'no telemetry, no analytics, no crash reporting, and no update check'. VERIFIED machine constraints that decide the Swift question: Command Line Tools only (no xcodebuild, xcstringstool, xctrace, actool), but notarytool 1.1.2 and stapler ARE present, SwiftUI apps DO build with `swift build`, .strings/.stringsdict localisation and ad-hoc `codesign --options runtime` work on a hand-assembled .app, whereas `.xcstrings` catalogs are copied uncompiled (lookups return the key) and `swift test` is non-functional (no XCTest; Swift Testing compiles with explicit -F but its runner dies on a missing lib_TestingInterop.dylib). The only signing identity on the machine is 'Apple Development', so a Developer ID certificate (99 USD/yr program) is a prerequisite for any signed release in either stack; the notarization toolchain itself needs no Xcode. GitHub Actions is free for this public repo, macos-latest is macOS 26 arm64 with Xcode 26.6 (so Swift tests and xctrace can run in CI even though they cannot run locally). Recommended minimal setup: one repo, `just` as the single task runner, a root `i18n/en.json`+`de.json` as the one string source with generated per-stack artifacts (i18next JSON import for web, .strings/.stringsdict + key enum for Swift), CLI English-only and machine-oriented, a two-file settings model (app settings.json with <=8 keys, vault `.novalis/config.json` for kanban) enforced by a deny_unknown_fields struct plus a snapshot test, ADR log + PR gate for every new setting/feature/dependency/network call, tag-driven releases with no auto-update (keep the old promise; Homebrew cask as the update path), a small test pyramid (core unit + fixture vault, CLI golden, one accessibility-driven smoke) with explicit performance budgets measured by hyperfine and /usr/bin/time -l in CI, and an orphan-branch cut-over that renames old main to `legacy`, keeps the repo URL, and rewrites the ruleset's required-check names. Everything beyond the brief is listed under owner decisions.
