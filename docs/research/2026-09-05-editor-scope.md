## SUMMARY
Scope research for the minimal novalis v1 (notes + Sublime-like text editor), based on reading the old novalis repo (/Users/sgrundhoefer/Projects/novalis: README, preferences.rs, keybindings.ts, notes/vault/index/trash modules), the demo vault (63 .md files, 228 wikilink occurrences), and primary docs for Sublime Text 4, Zed, CotEditor, BBEdit, iA Writer, Typora, Obsidian, Bear, Nota, CodeMirror 6 / Lezer, pulldown-cmark, Tauri spellcheck issues, and Apple's macOS shortcut list. Web tools (WebSearch, WebFetch) were available and used; library versions cited were fetched from npm/crates.io registries today (2026-09-05). Key results: (1) the editor feature set that makes an editor feel fast/complete is small and almost entirely built into CodeMirror 6 without settings: tabs, command palette, fuzzy goto-file, goto-line, in-file find/replace with regex, vault-wide search, multi-cursor (Cmd-D / Cmd-Shift-L / add-cursor), bracket matching, syntax highlighting, autosave, undo. Typewriter/focus, split view, folding, minimap, vim, LSP, plugins are LATER/NO. (2) For a text-editor-first product I recommend 'decorated source mode' (iA Writer style: all Markdown markers stay visible, only styled) plus an optional read-only preview; NOT Obsidian-style Live Preview and NOT TipTap/Typora WYSIWYG, for performance, predictability and byte-exact plain-text fidelity (the old app's tiptap-markdown round trip re-serialized files). (3) Flavor: CommonMark 0.31.2 + GFM 0.29-gfm extensions (tables, task lists, strikethrough, autolinks) + YAML frontmatter + [[wikilinks]] + inline #tags; nothing else (no callouts, highlights, embeds, block refs, math, mermaid). (4) Wikilinks: the demo vault depends on them (0 markdown-style .md links; 228 wikilinks) and, critically, only 23 of 59 unique link targets resolve by filename while all 59 resolve by frontmatter title — so the old vault relies on title-based resolution, which Obsidian does not do. This is the single most consequential owner decision: filename-based resolution (Obsidian/agent-simple, requires a one-time rename migration of ~36 files) vs title-index resolution (old-vault compatible, needs an index). (5) The old app's move_note did NOT rewrite links in other notes (verified in notes/mod.rs:347-360) and its link index only recognized [[...]] (index/links.rs:19); rename-with-link-rewrite must be new work. (6) File types: 11 Lezer-grammar types + 5 legacy-stream-mode types + plain text (csv/tsv/log), all lazy-loadable via @codemirror/language-data; stop there; no tree-sitter. (7) Proposed settings surface is 5-6 items (vault folder, language, appearance, font size via Cmd+/-, spellcheck via Edit menu, sync account); everything else hard-coded; every one flagged for owner approval. (8) Spellcheck caveat: in Tauri/WKWebView the native spellchecker works via right-click but red underlines are hidden (tauri-apps/tauri#7705, open since 2023-08-28, no fix) — needs a spike or NSSpellChecker via objc2-app-kit 0.3.2. (9) Keyboard: Apple-standard bindings plus the Sublime/Zed-convergent set (Cmd-P, Cmd-Shift-P, Ctrl-G, Cmd-D, Cmd-Shift-L, Cmd-Shift-F, Cmd-/), with one conflict to decide: Cmd-P = goto file (Sublime/Zed) vs macOS Print.

### F3. Markdown editing mode: recommend decorated source mode (+ optional read-only preview), not Live Preview, not WYSIWYG  [verified]
Options: (A) Source mode with decorations (iA Writer / Obsidian 'Source mode' + styling): every character stays visible; headings sized, emphasis styled with markers kept, links/tags colored, code fences monospace tinted, task checkboxes clickable, wikilinks Cmd-click. (B) Hybrid Live Preview (Obsidian default, 'shows formatted text inline while hiding most Markdown syntax', syntax reappears when the cursor enters it). (C) WYSIWYG (Typora; old novalis via TipTap 3.30 + tiptap-markdown 0.9 with markdownRoundTrip tests in packages/editor/src). Trade-offs: Performance — A: Lezer incremental parse + plain highlighting, O(viewport); B: widget/replace decorations that must be recomputed around every selection change, breaks with multi-cursor (each cursor reveals syntax), tables and HTML need special casing; C: ProseMirror DOM model, heaviest on long documents, and code files cannot use it at all (two editor engines in one app). Predictability — A: cursor position == byte position, find/replace and multi-cursor operate on what you see; B: 'where did my asterisk go' cursor jumps, hidden characters affect column selection; C: hidden model, keyboard behaviour differs from every other file type. Plain-text fidelity — A and B: byte-exact, only the user's keystrokes change the file; C: file is re-serialized from a document model (normalizes list markers, escapes, whitespace), which causes spurious diffs and increases Drive/OneDrive conflict surface. For a product that is 'a clean, high-performance text editor like Sublime' first, A is the only option that lets .md and .rs share one editor, one keymap, one find/replace and one multi-cursor implementation. Recommendation: A, hard-coded; plus SHOULD: a read-only rendered preview (Cmd-E toggle as in Obsidian) rendered by the Rust core with pulldown-cmark 0.13.4 (already the old core's parser, 0.13 line) — useful for reading long notes and for tables. NO 'default mode' setting (old app had default_reading_mode).

### F4. Markdown flavor and the wikilink decision (with demo-vault data)  [verified]
Flavor recommendation: CommonMark 0.31.2 (2024-01-28) + the GFM 0.29-gfm extensions Tables, Task list items, Strikethrough, Autolinks (skip 'Disallowed Raw HTML' since we do not render untrusted HTML) + YAML frontmatter block delimited by --- at file start + [[wikilinks]] + inline #tags. Parser support verified: @lezer/markdown 1.7.2 ships GFM bundle (Table, TaskList, Strikethrough, Autolink) and is extensible via BlockParser/InlineParser (wikilinks and tags = small custom inline parsers); @codemirror/lang-yaml exports yamlFrontmatter({content}) to nest the Markdown language under a frontmatter block; pulldown-cmark 0.13.4 has ENABLE_TABLES, ENABLE_TASKLISTS, ENABLE_STRIKETHROUGH, ENABLE_YAML_STYLE_METADATA_BLOCKS, ENABLE_WIKILINKS ('Obsidian-style'), ENABLE_GFM, ENABLE_FOOTNOTES, ENABLE_MATH. Explicitly NOT in v1: callouts, ==highlights==, %%comments%%, ^block-ids, ![[embeds]], math, mermaid, footnotes (LATER; parser has it), definition lists, heading attributes. Demo vault facts (63 files): 228 wikilink occurrences, 59 unique targets, ZERO markdown-style [text](x.md) links; inline #tags at note bottoms (reading 15, idea 14, summary 11, pkm 10, ...); frontmatter keys: title/created/modified in all 63, status 40, rating 21, project 15, author 8, date/start/end/type 6 (calendar events). Resolution: only 23/59 unique targets match a filename, all 59 match a frontmatter title (e.g. [[Local-First Software]] -> research/local-first-software.md). Obsidian, iA Writer and agents resolve [[X]] by FILENAME; the old novalis resolved by title + aliases via a SQLite index (notes/mod.rs resolve_note_path, 'exact case-insensitive title match first, then an alias fallback'). Wikilinks vs [text](path.md): durability/portability favor Markdown links (render everywhere incl. Drive/OneDrive web previews; CommonMark; no resolver needed; unambiguous for CLI agents) but they require %20-encoding of spaces (Obsidian docs) and rewriting on every move; wikilinks favor writing ergonomics ([[ autocomplete, no encoding), Obsidian/Bear/iA interop, and the existing vault. Recommendation: parse and follow BOTH; generate [[wikilinks]] from the [[ completion; resolve by filename (case-insensitive, shortest path wins on duplicates, optional [[folder/Name]] and [[Name|alias]]) so no index is required for correctness and the CLI/agents get a deterministic rule; provide a one-time migration command that renames files to their frontmatter title (about 36 files in the demo vault) or rewrites links. Title-based resolution is the alternative if the owner will not rename files.

## RECOMMENDATIONS

### R1. Build one editor for all file types (CodeMirror 6 if webview) in 'decorated source mode': Markdown is highlighted and lightly styled but never hidden or re-serialized; add a read-only rendered preview toggle (Cmd-E) rendered by the Rust core (pulldown-cmark 0.13.4).
Byte-exact fidelity, one keymap/find/multi-cursor implementation shared by .md and .rs, O(viewport) performance, fewer sync conflicts; matches the 'Sublime-like' brief.
_rejected: Obsidian-style Live Preview (hidden-syntax widgets fight multi-cursor/find, cursor jumps, table/HTML special cases); TipTap/Typora WYSIWYG (re-serializes files, second editor engine for code files, heaviest DOM)._

### R2. Ship the MUST editor set with zero settings: tabs, command palette (Cmd-Shift-P), fuzzy goto file (Cmd-P), goto line (Ctrl-G), in-file find/replace with regex, vault-wide search (Cmd-Shift-F), multi-cursor (Cmd-D, Cmd-Shift-L, Ctrl-Shift-Up/Down, Alt-click), bracket matching, syntax highlighting, hard-coded soft wrap/line numbers per file type with transient palette toggles, debounced atomic autosave, large-file fallback.
This is the intersection of Sublime, Zed and CotEditor that makes an editor feel complete; all of it is built into CodeMirror 6 packages (view 6.43.11, search 6.7.2) and needs no preference UI.
_rejected: Split view, folding, typewriter/focus mode, minimap, vim, LSP, terminal, plugins — each adds state or a mode; deferred to LATER/NO._

### R3. Markdown flavor = CommonMark 0.31.2 + GFM tables/task lists/strikethrough/autolinks + YAML frontmatter + [[wikilinks]] + inline #tags, hard-coded; parse and follow both [[wikilinks]] and [text](path.md); generate wikilinks from [[ completion; resolve [[Name]] by filename (case-insensitive, shortest path on duplicates), not by frontmatter title.
Existing vault is 100% wikilinks (228 occurrences, 0 markdown .md links); filename resolution is deterministic, index-free and what Obsidian/iA/agents expect; markdown links stay first-class for portability.
_rejected: Markdown-links-only generation (requires %20 encoding for 'Harbor Overview.md'-style names, breaks Obsidian interop); title-based resolution as in old novalis (needs an index, ambiguous for agents) — offered as the fallback if the owner will not migrate filenames._

### R4. Note organization MUST set: folder tree, fuzzy open, vault full-text search, rename/move with link rewriting (new work), trash via macOS system Trash (trash crate 5.2.7); SHOULD: tags as a search filter, backlinks list, [[ and # completion, conflict-copy on concurrent external change. Drop from old core: toolbar, slash menu, callouts, outline panel, reading-mode default, tasks/@due parsing, Today, calendar, reminders, version history, in-vault trash UI, folder colors, manual ordering, graph, properties, image paste (LATER).
Brief says organizing/creating/writing/editing Markdown with Kanban content outside notes; everything dropped either belongs to the removed tasks/calendar domains or adds UI without improving organization.
_rejected: Keeping in-vault .novalis/trash (syncs across devices but needs a restore/empty UI); keeping version history (Drive/OneDrive already keep versions)._

### R5. Use an in-memory index (filenames, titles, tags, links) built at vault open and kept current by notify 8.2.0 events; no SQLite/FTS/HNSW in v1; expose the same index through the CLI for agents.
Removes a whole subsystem (old core: rusqlite + FTS + vectors + migrations) and stale-index bugs; vault sizes in scope are small (demo: 63 files).
_rejected: SQLite FTS5 (LATER if vaults exceed a few thousand notes); tantivy 0.26.1 (over-scoped)._

Declared file types: md/markdown, txt, json, yaml/yml, toml, xml/svg, html/htm, css, js/ts (+jsx/tsx/mjs/cjs), py, rs, sh/bash/zsh, ini/conf/cfg/properties/env, swift, Dockerfile, csv/tsv/log as plain text; load grammars lazily via @codemirror/language-data; Lezer where available, legacy stream modes for toml/ini/shell/swift; no tree-sitter.
