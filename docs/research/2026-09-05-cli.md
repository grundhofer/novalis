## SUMMARY
Researched prior art (Obsidian CLI 1.12, zk, nb, Dendron, Logseq CLIs, jrnl, khoj, Basic Memory MCP, three Obsidian MCP servers), agent-CLI design guidance (arcjet, Trevin Chow, agentsurface, GitLab issue #8177, gh formatting rules), the MCP 2026-07-28 spec, Claude Code SKILL.md rules, and the existing novalis-core crate + demo vault to design a headless `novalis` CLI for AI agents. The strongest pattern in the field is a headless binary that owns the core (zk, Basic Memory) rather than a remote control for a running GUI (Obsidian CLI, Logseq CLI both require the app running, which agents dislike); novalis already has a UI-agnostic Rust core (`crates/novalis-core`, 28k lines) with SQLite FTS5 index, WAL + 5s busy_timeout, atomic writes, a query DSL, backlinks/orphans/unresolved-link code, trash, and `@due/@status` task parsing, so the CLI can be a thin clap binary over the same crate. Two verified gaps matter for the design: (1) the old core's `move_note` does NOT rewrite `[[wikilinks]]` (links are stored by `target_title` and resolved by title/alias, so folder moves are safe but title renames break links), and (2) the old Kanban is derived from `@status(...)` inside notes, whereas the brief wants Kanban content outside notes, so a board store must be defined (owner decision). Concurrency with the desktop app works today by construction: the index DB lives in the OS app-data dir (never in the synced vault, per SQLite WAL constraints), the desktop watcher (notify 8, 300 ms debounce) reindexes any external `.md` write and ignores dot-prefixed temp files, so CLI writes via the core's `write_atomic` are picked up automatically; the missing piece is an optimistic `--if-match <sha256>` guard so an agent never clobbers an editor buffer silently. Proposed minimal surface: 13 top-level commands (`ls, cat, new, edit, meta, mv, rm/trash, search, links, tags, kanban, index, doctor`) plus `sync status`, `help --json`, with explicit `--json`, bare-JSON stdout, JSON errors on stderr, 7 stable exit codes, `--dry-run` on every mutation, no prompts ever, deterministic ordering, and note addressing by vault-relative path or title/alias. MCP is recommended as a phase-2 `novalis mcp` stdio subcommand in the same binary (rmcp 3.2.0, ~10 tools annotated with readOnly/destructive/idempotent hints) sharing the exact serde output types with the CLI, and only if the owner wants clients without shell access. For "wisdom organization" the CLI should expose primitives only (list/read with sha256, search, link graph, relink, move, edit-by-section, meta, trash, doctor) and leave merge/dedupe/tagging/MOC judgement to the agent; the one primitive beyond the brief that makes merges safe is `relink <from> <to>`. A shipped SKILL.md (Agent-Skills-portable fields only, <150 lines, reference.md + examples.md) is outlined. Tools used: WebSearch, WebFetch, curl to crates.io/GitHub raw; all local claims are from reading the old repo and demo vault.

### F2. Old core does NOT rewrite wikilinks on move/rename; links are keyed by title (VERIFIED)  [verified]
`notes::move_note` (notes/mod.rs L347-361) only calls `vault_fs::move_note` (fs rename), `versions::rename`, `change::remove(from)`, `change::reindex_path(to)`. Grep for `rewrite|relink|update_links|rename_links` across core + desktop finds nothing except the Notion importer. The `links` table is `(source_path, target_title)`; the wikilink regex is `\[\[([^\[\]]+)\]\]` (no path/alias/heading syntax parsed); resolution (`resolve_note_path`) is case-insensitive title match, then alias match, ties → most recently modified. Consequence: a folder move keeps `[[Title]]` links valid; a title/filename-stem rename silently dangles every backlink. The brief asks for `mv (with link rewriting)`, so the new core must add a `relink(old_title, new_title)` primitive that uses backlink rows to rewrite `[[old]]`, `[[old|label]]`, `[[old#heading]]` in each linking file (obsidian-cli and Obsidian 1.12 `move`/`rename` do this; Obsidian's only 'if turned on in vault settings').

### F3. Concurrency with the desktop app: index outside the vault, WAL + busy_timeout, watcher reindexes external writes (VERIFIED)  [verified]
Index DB path: `<app_data_dir>/db/notes.db` (vault/config.rs `db_path`), app id `com.novalis.desktop`; `.novalis/config.json` and `.novalis/trash` live inside the vault (synced). `index::schema::open_db` sets `PRAGMA journal_mode=WAL` and `busy_timeout(5s)` explicitly to tolerate 'a second app instance still holding the same notes.db'. SQLite WAL: 'All processes using a database must be on the same host computer' and 'WAL does not work over a network filesystem' — so the index must never sit inside a Drive/OneDrive folder (sync clients would also upload `-wal`/`-shm` and clobber across devices). Desktop watcher (`apps/desktop/src-tauri/src/watcher.rs`): `notify` 8 + `notify-debouncer-mini` 0.7, 300 ms debounce, recursive; skips non-`.md`, any dot-prefixed path component (incl. `.novalis`), and `~` temp names; skips paths registered by `mark_self_write` within `SELF_WRITE_WINDOW = 2s` (commands.rs L36-70); everything else → `change::reindex_path_with_opts` + emits `note-changed`/`note-deleted`; filenames matching ` (N).md` or `-DESKTOP-XXXX.md` emit `conflict-detected`. `vault::fs::write_atomic` writes `.<name>.<uuid>.tmp` in the same dir, fsyncs, renames — the temp file is ignored by watcher/walker/index. Therefore: a CLI process that (a) opens the same `notes.db` and (b) writes through `write_atomic` is picked up by the running desktop automatically, and its own index update is idempotent with the watcher's. Gap: no optimistic-concurrency guard exists; a CLI write while the editor has unsaved changes is last-writer-wins.

### F6. Agent-friendliness rules distilled from field guidance (VERIFIED sources; the synthesis is mine)  [verified]
Consensus across arcjet, Trevin Chow's '10 principles', agentsurface, GitLab CLI issue #8177 and gh: (1) never prompt — hanging on TTY prompts is the #1 reported agent failure (glab `ci view`); (2) stdout = data only, stderr = errors/diagnostics; (3) `--json` on EVERY command incl. mutations ('an agent doesn't know which commands are important'); gh's rule is JSON only when explicitly requested, arcjet suggests TTY-detect; (4) stable, small exit-code table (arcjet: 0 ok / 1 general / 2 auth / 3 validation / 4 confirmation-required; glab proposal: 0/1/3 auth/4 not found); (5) structured errors with `code`, `message`, `hint`/`remediation`, and enumerate valid values when rejecting input; (6) `--dry-run` + explicit `--force` for irreversible ops; idempotent creates return `existing:true`; (7) bounded output: `--limit`, `--fields`, truncation flag with a hint; (8) self-description: `--help` with realistic examples plus a machine-readable command tree (`agent-context`/`--agent-info`) and a shipped skill; (9) contracts are immutable post-1.0: add fields/flags, never rename/remove; (10) `doctor` command for prerequisites. Logseq-cli adds NDJSON + stdin composition; Basic Memory adds `expected_checksum` on edits.

### F8. Principles to hard-code (VERIFIED sources; application to novalis is my synthesis)  [likely]
1. Vault = source of truth: the CLI never stores anything an agent needs outside `.md` files, `.novalis/config.json`, `.novalis/kanban/*` and `.novalis/trash/`; the SQLite DB is a rebuildable cache in app-data (`novalis index --rebuild` must always recreate it losslessly). No second data model: CLI JSON = serde of the same core structs the desktop uses over IPC. 2. Index freshness: every index-backed read (`ls`, `search`, `links`, `tags`) first runs `incremental_index` (mtime walk; zk indexes on demand the same way) so agent edits made with their own file tools are visible immediately; `--no-index` skips it. 3. Direct file edits by agents are legitimate: the watcher and incremental index treat them like any external write; the CLI `edit` exists for frontmatter safety, `modified` stamping, atomicity and `--if-match`, not as a gate. 4. Idempotence: `new --exist-ok`, `meta --set` (set-if-different), `kanban card mv` (no-op if already there → `changed:false`), `mv` to same path → no-op; `--dry-run` on all mutations. 5. Determinism: fixed sort orders (documented above), stable field order, no timestamps in output except data fields, no ANSI unless TTY. 6. Concurrency: open DB with the existing `open_db` (WAL, busy_timeout 5 s); on SQLITE_BUSY exit 6 with `hint:"retry"`; write files through `write_atomic` (dot-tmp + rename, ignored by watcher); `--if-match` sha256 guard; never lock the vault. Desktop side must reload a note on `note-changed` if the buffer is clean, and show 'changed on disk' if dirty (desktop task, flag). 7. Non-interactive always: no prompts, no `--yes` needed; the only irreversible command (`trash empty`) needs `--force`. 8. Output bounded: `--limit` defaults (ls unlimited but `--fields`, search 50, tags all), `truncated:true` + hint when capped. 9. Language: CLI text/English only (agents); German lives in the desktop UI — owner decision.

### F9. MCP: phase-2 `novalis mcp` stdio subcommand in the same binary (VERIFIED versions; recommendation ASSUMED)  [verified]
MCP current spec revision is 2026-07-28 (sessionless; `server/discover`; backwards compatible with 2025-11-25 and earlier handshake versions). Tool annotations in the 2026-07-28 schema: `readOnlyHint` (default false), `destructiveHint` (default true, meaningful only when readOnlyHint==false), `idempotentHint` (default false), `openWorldHint` (default true; 'the world of a memory tool is not' open). Tool results carry `content` + optional `structuredContent` with `outputSchema`; execution errors use `isError:true`. Rust SDK: `rmcp` 3.2.0 (2026-08-31, Apache-2.0), features `server` + `macros` (default) + `transport-io` (stdio, not default); `#[tool]`/`#[tool_router]` macros; `rmcp::model::ToolAnnotations{read_only_hint,destructive_hint,idempotent_hint,open_world_hint}`. ### F10. Wisdom-organization split: core primitives vs agent judgement (ASSUMED design)  [assumed]

## RECOMMENDATIONS

### R1. Build the CLI as a headless Rust binary (`apps/cli` or `crates/novalis-cli`, clap 4.6) that links the new shared core crate directly — no IPC to the desktop app, no daemon.
Agents reject tools that need a GUI running (Obsidian CLI, Logseq CLI); zk and Basic Memory prove the headless model; the existing core is already UI-agnostic and takes only `(db, vault, data_dir)`. Concurrency is already handled by WAL + busy_timeout + the desktop watcher reindexing external writes.
_rejected: Obsidian-style IPC remote control (needs app running; agents hang); a long-running local HTTP API like Logseq (extra process, auth, ports); a Node/TS CLI (would duplicate the Rust core's parsing/indexing = second data model)._

### R2. Keep the SQLite index OUT of the vault (per-user app-data/cache dir, one DB per vault keyed by canonical path hash), shared by desktop and CLI on the same host; keep `.novalis/config.json`, `.novalis/kanban/`, `.novalis/trash/` inside the vault so they sync.
SQLite WAL requires same-host shared memory and explicitly does not work over network filesystems; Drive/OneDrive clients would also upload `-wal/-shm` files and corrupt the index across devices. The old app already uses this split and it is the reason CLI+desktop coexistence works.
_rejected: zk-style `.zk/notebook.db` inside the notebook (fine for git-synced notebooks, wrong for Drive/OneDrive-synced vaults)._

### R3. Ship the 13-command surface in the findings table with: explicit `--json` (auto when stdout is not a TTY), bare JSON on stdout, JSON error object on stderr, exit codes 0/1/2/3/4/5/6/7, `--dry-run` on every mutation, zero prompts, `--force` only on `trash empty`, deterministic sort orders, `--if-match <sha256>` on `edit`/`meta`.
Matches the consensus of every agent-CLI guideline found (arcjet, Trevin, agentsurface, GitLab #8177, gh) and the two most agent-used note tools (zk, Basic Memory). Bare JSON keeps `jq` pipelines and agent context small.
_rejected: JSON envelope `{ok,result,error}` on stdout (extra bytes, and exit code + stderr already carry that); NDJSON-by-default (harder for agents to read whole results; offer `--jsonl` later only if asked); `key=value` Obsidian syntax (non-standard for clap and humans)._

### R4. Add one new core primitive the old core lacks: `relink(old_title, new_title)` that rewrites `[[old]]`, `[[old|label]]`, `[[old#heading]]` in all backlinking notes and kanban card refs; `mv` calls it automatically when the title changes; expose it as `novalis relink` (flagged for owner decision).
The brief asks for `mv` with link rewriting and the old `move_note` verifiably does not do it. Merge/dedupe workflows need the same operation independently of a move.
_rejected: Alias-only approach (`meta --add-alias old`) keeps links resolving but hides broken references and fails once the alias is removed; path-based links (Obsidian shortest-path) would change the vault format._

### R5. Auto-run the mtime-based incremental index before every index-backed read (`ls`, `search`, `links`, `tags`, `doctor`), with `--no-index` to skip and `index --rebuild` for a full rebuild.
Agents also edit files with their own tools; zk does the same on-demand indexing; the old core's `incremental_index` already exists and is O(files) stat calls.
_rejected: Requiring a running desktop app or a background daemon to keep the index fresh._

### R6. Defer MCP to phase 2 as `novalis mcp` (stdio, rmcp 3.2.0, `transport-io` feature) inside the same binary, wrapping the same serde output structs with schemars-generated `outputSchema` and full annotations; ship only if the owner wants clients without shell access.
Claude Code/Codex already drive CLIs via Bash + a skill; MCP costs tokio + a second interface to keep in sync; sharing handlers avoids drift. The MCP 2026-07-28 spec and rmcp both support the needed annotations.
_rejected: Separate MCP crate/process (duplication); MCP-first with no CLI (Basic Memory's path; loses shell composability and requires a client)._

### R7. Ship a portable Agent-Skills `SKILL.md` (+ `reference.md`, `examples.md`) in the monorepo, exposed via `novalis skill --path` and `help --json`; do not auto-install into `~/.claude`.
Claude Code docs: skills are the intended discovery mechanism, description budget is 1,536 chars and every skill costs context per turn, so keep it short and progressive. Auto-installing into user config is a setting the owner wants to be asked about.
_rejected: Baking usage docs only into `--help` (agents rarely read long help); a Claude-Code-only skill (breaks Codex/claude.ai portability)._

### R8. Expose only primitives in the CLI (list/read+sha256, search, links graph, relink, mv, section edits, meta, trash, doctor); keep merge/dedupe/tag-suggestion/MOC logic on the agent side; no LLM calls inside the CLI.
The owner wants minimal features; judgement belongs to the agent; primitives compose. This mirrors zk (graph filters) and Basic Memory (edit ops) which agents use well.
_rejected: Built-in `merge`, `suggest-tags`, `similar` commands (each is a feature+setting; `similar` needs embeddings)._

## OWNER DECISIONS
- Kanban store: format and location for board/card data that lives outside notes — proposed `<vault>/.novalis/kanban/<board-slug>.json` (synced with the vault, hidden from note listing), cards referencing notes by vault-relative path (kept in sync by `mv`/`rm`). Alternative: a visible `kanban/` folder of JSON or a single `kanban.json`. This decision may belong to the Kanban researcher; the CLI just needs it fixed.
- Do inline tasks (`- [ ] … @due()`) survive in the new novalis at all? If yes, the CLI needs a `tasks` command (old core has it); if no, `search` DSL loses `task.*` facets and `doctor` need not check them.
- Should `relink <from> <to>` be a public command (beyond the brief) or only an internal step of `mv`?
- Should `meta` (frontmatter set/unset/tags/aliases) be a separate command, folded into `edit`, or omitted (agents edit YAML directly and the strict parser only warns)?
- Is `novalis init <dir>` (create `.novalis/config.json`, enabling cwd walk-up discovery) acceptable, or should the CLI require `--vault`/`$NOVALIS_VAULT` only?
- `sync run` in the CLI: only meaningful if the app gets in-app Google Drive/OneDrive OAuth sync; with local-folder sync, `sync status` (cloud-only placeholders, conflict copies) is all that exists. Which one?
- `doctor --fix` (auto-repair: rebuild index, stamp missing `created`/`modified`, quarantine broken frontmatter) — include, or keep doctor read-only?
- MCP at all? If yes, phase 2 in the same binary as recommended; if the owner never expects Claude Desktop/ChatGPT-style clients, skip it entirely.
- CLI language: English-only output/help for agents (recommended) vs German+English help text (i18n cost, agents don't need it).
- Templates for `new` (old core had JSON templates in app-data) and per-note version history — both exist in the old core; the brief did not ask; recommend omit.
- `help --json` / `skill` self-description commands: small, but they are two extra commands — confirm they are wanted.
- Desktop behaviour on external CLI writes: auto-reload clean editor buffers and show a 'changed on disk' banner for dirty ones (needed so `--if-match` guarantees hold end-to-end) — a desktop decision the CLI depends on.
