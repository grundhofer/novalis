## Deviations
1. .state-waiting .state-word stays amber #C25E00 on the white card (4.29:1 at 10px caps, 0.21 under AA for small text). Accepted deliberately rather than fixed: the hex is the spec's own accessible-amber value and I will not derive a darker amber silently; the offered alternative (word in --ink-soft) would make the waiting word a grey that reads as the idea state's grey (#5B5B5B) and break the one-colour-per-role rule; and the state is carried by three redundant channels (outlined amber square, the word text, the column position), so meaning survives even if the word is the weakest text on the board. Dark mode (#E08A3C on #1E1E1E) passes comfortably. If the owner wants strict AA here, the clean route is to change the light amber token itself (e.g. #B85A00, 4.67:1) at spec level.

2. .line.h2 weight 600 -> 500 was not in the violation list. Changed as a direct consequence of the requested h1 change (see notes 5) to keep h1 >= h2 in weight; flagged here because the brief said to keep everything else unchanged.

3. .tree .file.conflict .meta is hidden (display:none) instead of shown in red; the violation offered this as one of two acceptable routes, but it does remove the visible word "Konfliktkopie" from the tree row itself. The badge and the foot hint retain it.

4. The original .board-name (20px/400) and headings at 600 were an unstated departure from the spec's thin-title signature; that is now corrected, but the spec's literal "Weight 200-300, 48-56px, Tracking -0.035em" title setting is still not used anywhere, because no app-window element in these layouts is that large. The 22px/300 board title is the demo's own secondary-title compromise.

## Critic summary
Flat stylesheet reviewed against spec, skeletons, base.css and CLASSES.txt, then rendered in Chrome (all 5 layouts, light + dark, real Work Sans / Geist Mono) and measured. (a) Scoping: clean. Every selector starts with .style-flat, no at-rules, no url()/gradients/filters/backdrop, exactly one box-shadow token (card + palette), radius 4px throughout; border-radius:50% appears only on circular glyphs (status/state dots, ring marks). (c) Coverage: complete. .card.selected (2px blue ring via border+inset outline, bolder title), .badge-cloud, .badge-conflict, .board-item (drawn two-pane glyph + caps BOARD), .line.cursor (4% lift + 2px accent caret), .tab/.tab.active/.tab-close, .scrim/.palette/.palette-input/.results/.result.active/.palette-foot/.kbd, .split-note hairline, status teal dot, hint + hint-dot, .legend, col-count, btn.primary/ghost are all styled; the dark token set overrides every light token that carries colour (only --shadow/--radius/--t/fonts are shared, which is correct). Status coding is three-channel (colour + shape + word) and every interactive element has a second marker. (d) Fit: CONFIRMED by render. Statusbar bottom = 800px in every layout; editor slack 33px (l2, l3, l5) and 69px (l1) with all 26 lines visible; board columns use 302-494px of 590-662px available; 14 tree rows end at 465px; palette bottom 373px; no horizontal overflow in tabs, statusbar or board-head. Only cosmetic fit issues (below). (b/e) Real problems found: one medium contrast failure (--ink-faint used for informational 10-11px text at 3.06-3.36:1 light / 3.99-4.34:1 dark), plus low items: amber state-word 4.29:1, primary-button hover 4.16:1 (spec's own hover value), dark hover shift 9.4 L-points (band is 4-8), 2px strokes on the waiting mark vs the 1.5px icon rule, the spec's thin-title signature absent, the flex .hint cannot show an ellipsis, l5 code line wraps, and depth-1 tree names truncate hard. Palette note: all light chrome values match the demo (#0A6CA8/#0D82C9/#08587F/#0E7A5F/#B81100/#C25E00/#5B5B5B/#141414/#6E6E6E/#8C8C8C/#E2E2E2/#CFCFCF); #F4F4F4 canvas, #EDEDED/#E9E9E9 surfaces, #EBF3F8 tint, the entire dark set, and the macOS traffic-light colours are derivations the spec does not supply and must be declared in the notes (allowed by rule 3, not a violation).

## Violations found by the critic
- [medium/contrast] .style-flat .tree .meta, .style-flat .legend, .style-flat .card-when, .style-flat .result-meta, .style-flat .badge-cloud, .style-flat .tree .board-item .meta (all via --ink-faint): --ink-faint (#8C8C8C light / #7C7C7C dark) is used as the text colour for informational 10-11px text. Measured: 3.06:1 on the #F4F4F4 canvas (tree dates, legend, board-item BOARD label, cloud badge) and 3.36:1 on #FFFFFF (card-when, result-meta); dark 4.34:1 / 3.99:1. All below 4.5:1 for small text; the spec states 'Kontrast: hoch' and the demo uses #8C8C8C only for input placeholders. → Keep --ink-faint only where receding is the point (.marker, .line.fm, .lang, .tab-close). Switch the informational uses to var(--ink-soft): #6E6E6E gives 4.64:1 on #F4F4F4 and 5.10:1 on #FFFFFF; dark #A3A3A3 gives 7.17:1 / 6.61:1. Concretely: .tree .meta, .legend, .card-when, .result-meta, .badge-cloud, .tree .board-item .meta -> color: var(--ink-soft).
- [low/contrast] .style-flat .state-waiting .state-word: Amber #C25E00 on the white card at 10px uppercase measures 4.29:1, under 4.5:1. The value is the spec's own accent, and shape + word are redundant channels, so meaning survives, but the word itself is the weakest text on the board. → Either accept and state it in notes (colour is redundant to shape and text), or keep amber on the .state-mark only and set .state-waiting .state-word to var(--ink-soft); a darker amber such as #B85A00 (4.67:1) would pass but departs from the spec value, so do not derive silently.
- [low/contrast] .style-flat .btn.primary:hover: White label on hover blue #0D82C9 measures 4.16:1 (rest state 5.64:1). It is the demo's own hover value and transient, but the 12px label dips below 4.5:1 while hovered. → Shift hover darker instead of lighter while staying inside the 4-8% band, e.g. --blue-hi: #095F94 (6.83:1 with white, HSL lightness shift of about 4 points), or accept as transient and note it.
- [low/spec] .style-flat[data-theme="dark"] --hover (#2E2E2E) and .style-flat .result:hover: Spec hover rule is a 4-8% lightness shift. Dark tree/tab hover #161616 -> #2E2E2E is +9.4 HSL lightness points; light .result:hover #FFFFFF -> #E9E9E9 is -8.6 points. Both just outside the band (light tree/tab -4.3 and ghost button -7.1 are fine). → Dark: --hover: #2A2A2A (+7.8 points, and it equals --surface-2 so the palette stays at one step). Light: .result:hover { background: var(--surface-2); } (#EDEDED, -7.1 points).
- [low/spec] .style-flat .state-waiting .state-mark, .style-flat .col-3 .col-head::before: Spec icon rule is 1.5px outline strokes; the waiting mark and its column-head twin use border: 2px while the idea ring uses 1.5px, so the four marks do not share one stroke weight. → border: 1.5px solid var(--amber) on both, matching .state-idea .state-mark; if the square needs more presence, enlarge it to 9px rather than thickening the stroke.
- [low/spec] .style-flat .board-name, .style-flat .line.h1: The spec's one typographic signature ('extreme Gewichtsspreizung', thin large titles; the demo's secondary title is weight 300 with -0.02em) is absent: weights used are 400/500/600 only, board-name is 20px/400 and the editor h1 is 24px/600. Not a hard-parameter breach at app sizes (the spec itself warns thin weights break under ~300 at small sizes), but it is an unstated departure. → Either declare it as a deliberate deviation in the notes, or take the demo's secondary-title setting: .board-name { font-size: 22px; font-weight: 300; letter-spacing: -.02em } and .line.h1 at weight 500, keeping 500/600 for 12-14px UI text where weight 300 would break.
- [low/fit] .style-flat .hint: text-overflow: ellipsis cannot apply here: .hint is display:flex and the text is a bare text node (an anonymous flex item), so on overflow it hard-clips instead of eliding. Render measured 210px of content in 215px available, so it currently fits by 5px; a slightly wider font render or a longer count would clip 'Konfliktkopie' mid-word without an ellipsis. → .style-flat .hint { display: block; } and .style-flat .hint-dot { display: inline-block; vertical-align: middle; margin-right: 6px; } so the ellipsis works, or shrink the hint to 10.5px.
- [low/fit] .style-flat.layout-l5 .line.code .txt: In the 472px split-note pane the 57-character JSON line at 12px Geist Mono needs ~410px but only ~408px remain after the 10px .txt padding; render confirms line 20 wraps to 40px with a lone '}' on the second line. Nothing overflows (33px slack remains), purely cosmetic. → .style-flat.layout-l5 .line.code .txt, .style-flat.layout-l5 .line.fence .txt { padding: 0 8px; font-size: 11.5px; } or drop the l5 .doc side padding from 22px to 20px.
- [low/fit] .style-flat .tree .depth-1 (padding-left: 28px): Render shows three depth-1 names truncated hard: 'Conflict Resolution Patt…', 'Sync Strategie…', 'Zettelkaste…' (the last loses most of its name to the 11px 'Konfliktkopie' meta plus badge). The 28px indent (base uses 16px) plus 12px row padding leaves ~120px for the name in a 240px sidebar. Graceful (ellipsis works here) but the active vault's conflict row is barely identifiable. → Reduce the indent to 22-24px and set .tree .meta to 10.5px, or give .tree .file.conflict .meta a shorter treatment (e.g. hide the word and rely on the red ⚠ badge, which already carries the meaning).
