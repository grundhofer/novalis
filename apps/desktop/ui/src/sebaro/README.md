# sebaro design export: sebaro (profile desktop)

A copy of the sebaro design system for a desktop app: a window with panes in a webview. **Do not edit these files.** `checks/update-copy.mjs` fetches a newer release and writes this folder anew (section *Keep in sync*), and `CHANGES.md` says, release by release, what a product does after an update. `sebaro-export.json` lists every file with its sha256, and the packs of this copy. What a product needs to adopt the copy is in this README and in the files it names here; the last section is for the maintainers of sebaro alone. Generated by `tools/export_system.py` 1.34.0 (status of the system: draft).

| Item | Value |
|---|---|
| System | sebaro (`sebaro`), token contract 2.0 |
| Profile | `desktop`: a desktop app: a window with panes in a webview |
| Packs | `packs` in `sebaro-export.json` names the packs of this copy, `packsAvailable` every pack of the profile. This README is the same text for every choice (section *Profile and packs*) |
| Product | none. A profile copy knows no product: the product's sign, favicons, manifest, head snippet and app icon are its own files, made from its declaration with `product/` of this folder (section *Product files*), outside this folder |

## Moving a product here

For a product that comes from a `--target web` or `--target tauri` copy or from the npm package. A new product goes on with the next section. Four things change, and the first shows only on the screen.

**1. The start shows the product's colour and its bare sign.** Since design round 7 the start is a full screen in the colour of the product's tile with the bare sign in its middle, which fades to the page; the tile that travelled into the header is gone. The stylesheet takes the colour from the product's scope on `.sb-start`. With the old markup nothing sets it: the start is transparent and the page shows while it loads.

```html
<!-- before: the tile, and its target in the header -->
<div class="sb-start" aria-hidden="true"><span class="sb-start__tile"><!-- the tile, inline --></span></div>
<!-- after: the product's id on the start, and the bare sign inline (sign/sign.svg of the product's folder) -->
<div class="sb-start" data-sb-product="<id>" aria-hidden="true"><span class="sb-start__tile"><!-- sebaro-product/sign/sign.svg, inline --></span></div>
```

It stays the first element of `<body>`. `<html data-sb-start>`, `js/sb-start.js` in the head after `js/theme-init.js` and `data-sb-start-enter` on the content stay as they were; `data-sb-start-target` on the header's tile may stay and does nothing. The scope is the product's `product.css`, loaded after `tokens.css` (section *Product files*, *The product's scope*). `js/sb-start.js` is in the core.

**The window opens in the product's colour.** A desktop app's window has, from its first frame, the ground of the start: the tile colour of the product's group, not the light or dark ground, so no neutral ground shows before the start; the start then fades to the app in its stored light or dark ground. The colour is the one the kit draws the product's tile in: `groups.<group>.tile` of `product/tiles.json`, the same value as `signTiles.<group>.tile` of `tokens.json`, with `<group>` the `tile` of `sebaro.product.json`. `src-tauri/build.rs` reads it where it reads the four grounds, the window is created with it as its ground, and when the start is over (`sb-start-done`) the window takes the stored ground, so a resize later shows the app's.

**2. One stylesheet.** The imports of `css/parts/01-base.css` to `08-forced-print.css` (seven for a site without the window part) become the one `css/sebaro.css`: the rules of the core and of the packs this copy was written with, in the order of the whole file. A product that loaded only some of the parts names packs instead (section *Profile and packs*); `css/parts/` is in no copy.

```css
/* before */
@import "./sebaro/css/parts/01-base.css";   /* … and the other parts */
/* after */
@import "./sebaro/css/sebaro.css";
```

**3. A purge or cut script of the product's own** keeps its place in the build: the stylesheet with one pack is larger than a page budget of 90 KB (the sizes are under *Files*). Its hand-kept safelist is replaced by the copy's lists of what exists only at run time, and the script by the one of the section *Cut the stylesheet to what the pages use*, which keeps every selector as it is written. Paths to `css/parts/`, and to a file of a pack this copy does not hold, leave that script.

**4. The product's files come from the kit.** `brand/site-root/` (favicons, manifest, head snippet, `theme-color.json`), `brand/inline/sign-<id>.svg` and `tile-<id>.svg`, `tauri/icon-1024.png` and the `[data-sb-product="<id>"]` scope of `tokens.css` are in no profile copy, and no profile export takes `--product`: the copy is the same for every product. The product declares itself in `sebaro.product.json`, and the kit of this folder writes those files into `sebaro-product/`, a folder of the product. The section *Product files* has the two commands and a table of every file with where it is served or imported.

## Cut the stylesheet to what the pages use

A desktop app does not need this step: its files come from the disk, not from a network, and a cut is one more step that can go wrong. It is here for an app whose web build is also served as a site. The step is the product's own: it runs in the product's build, reads this folder and writes outside it.

**What exists only at run time** is what a cut cannot see in the pages. This copy lists it: `css/runtime-names.json` for the core and `css/runtime-names.<pack>.json` for each pack of the copy that holds a script or rules. `scripts` has, for each script, the classes, attributes, elements and custom properties it can set, add or toggle and the stylesheet has a rule for, the icons it can name, and apart from them the classes it only looks for (`asked`), which a cut does not need; `states` has the ARIA attributes of the rules. The lists are read from the scripts and the stylesheet when the copy is made (the head of each file says how), so they are right for the packs of this copy and change with them. A site's own safelist of sebaro names is not needed beside them.

**The stylesheet.** Save this as `cut-css.mjs` in the product (Node 20+, and `npm install --save-dev purgecss@8.0.0`, the version this step is tested with before a release):

```js
// cut-css.mjs: tokens.css and css/sebaro.css of the copy as one file, cut to what the site's pages use.
//   node cut-css.mjs <the sebaro copy> <output.css> <pages, scripts and the site's own CSS: files or folders>…
import fs from "node:fs";
import path from "node:path";
import { createRequire } from "node:module";
import { PurgeCSS } from "purgecss";

const postcss = createRequire(createRequire(import.meta.url).resolve("purgecss"))("postcss");   // purgecss's parser
const [copy, out, ...site] = process.argv.slice(2);
if (!site.length) {
  console.error("usage: node cut-css.mjs <the sebaro copy> <output.css> <pages, scripts, own CSS: files or folders>…");
  process.exit(2);
}

// The site's files. A page or a script is read for the words in it. A CSS file is read only for the custom
// properties it names, never for words: it names classes no page has to use. The output of an earlier run is skipped.
const walk = (p) => (fs.statSync(p).isDirectory() ? fs.readdirSync(p).flatMap((n) => walk(path.join(p, n))) : [p]);
const files = site.flatMap(walk).filter((f) => path.resolve(f) !== path.resolve(out) &&
  !/\.(png|jpe?g|gif|webp|avif|ico|woff2?|ttf|otf|pdf|zip|gz|mp[34]|webm|ogg|wav|map)$/i.test(f));
const text = (f) => fs.readFileSync(f, "utf8");
const words = files.filter((f) => !f.endsWith(".css")).map(text).join("\n");
if (!words) throw new Error("no page or script among " + site.join(", "));

// What exists only at run time: css/runtime-names.json of the copy, and one file for each pack it holds.
const names = { classes: [], attributes: [], tags: [], properties: [] };
for (const n of fs.readdirSync(path.join(copy, "css")).filter((n) => /^runtime-names(\.[a-z0-9-]+)?\.json$/.test(n))) {
  const doc = JSON.parse(text(path.join(copy, "css", n)));
  for (const part of [doc.states, ...Object.values(doc.scripts)]) {
    for (const kind in names) names[kind].push(...(part[kind] ?? []));
  }
}

// 1. Selectors. Every selector of a list is asked on its own and then kept or dropped as it is written. PurgeCSS
//    left to write the file would shorten the lists inside :is() and :where(), which changes what a selector weighs,
//    and would drop a selector made of pseudo-classes alone. A class, an element or an attribute counts as used when
//    a page or a script holds the word, or a script of the copy can set it; a pseudo-class always counts (/^:/), so
//    :hover, :target, :focus-visible and the like stay with their part.
const root = postcss.parse(["tokens.css", "css/sebaro.css"].map((f) => text(path.join(copy, f))).join("\n"));
const rules = [];
root.walkRules((rule) => { if (!/keyframes$/.test(rule.parent.name ?? "")) rules.push(rule); });
const [asked] = await new PurgeCSS().purge({
  content: [{ raw: words, extension: "html" }],
  css: [{ raw: rules.flatMap((rule, r) => rule.selectors.map((s, i) => `${s}{--keep:${r}_${i}}`)).join("\n") }],
  safelist: { standard: [...names.classes, ...names.tags, /^:/] },
  dynamicAttributes: names.attributes,
});
const keep = new Set(asked.css.match(/--keep:\d+_\d+/g));
rules.forEach((rule, r) => {
  const left = rule.selectors.filter((_, i) => keep.has(`--keep:${r}_${i}`));
  if (!left.length) rule.remove();
  else if (left.length < rule.selectors.length) rule.selectors = left;
});

// 2. Custom properties. One stays when a declaration that stays reads it, when a file of the site names it, when
//    the copy's icon rules read it (icons/sprite.css, which a page loads as it is) or when a script of the copy reads
//    it. A declaration in @keyframes counts like any other.
const named = [...files.map(text), text(path.join(copy, "icons", "sprite.css"))].join("\n");
const used = new Set([...names.properties, ...(named.match(/--[A-Za-z_][\w-]*/g) ?? [])]);
for (let grew = true; grew;) {
  grew = false;
  root.walkDecls((decl) => {
    if (decl.prop.startsWith("--") && !used.has(decl.prop)) return;
    for (const [, name] of decl.value.matchAll(/var\(\s*(--[\w-]+)/g)) {
      if (!used.has(name)) { used.add(name); grew = true; }
    }
  });
}
root.walkDecls(/^--/, (decl) => { if (!used.has(decl.prop)) decl.remove(); });

// 3. Comments go, and what is left empty. Never cut: @keyframes, and an at-rule as a whole: a rule in @media print,
//    forced-colors, @container or @supports stays when its selector does. (@font-face is in fonts/fonts.css, which is
//    no input.)
root.walkComments((comment) => comment.remove());
root.walk((node) => { delete node.raws.selector; delete node.raws.value; });   // a comment inside a selector or a value
for (let again = true; again;) {
  again = false;
  root.walk((node) => { if (node.nodes && !node.nodes.length) { node.remove(); again = true; } });
}
const css = root.toString();
fs.mkdirSync(path.dirname(path.resolve(out)), { recursive: true });
fs.writeFileSync(out, css);
console.log(`${out}: ${Buffer.byteLength(css)} bytes, ${rules.filter((rule) => rule.parent).length} of ` +
  `${rules.length} rules, read from ${files.length} file(s)`);
```

```sh
node cut-css.mjs sebaro dist/sebaro.cut.css dist src/site.css sebaro-product/sign/product.css
```

- **Input:** this folder; then every file that can put a class, an element or an attribute into a page: the built pages and the scripts the site loads, or the sources they are built from. And the site's own CSS files, `product.css` among them, which are read for the custom properties they name. A source hides what its renderer writes (Markdown names no `table`): cut from built pages where the build allows it, or add a text file that names those elements. Do not name a folder that holds a served copy of `tokens.css` or `css/sebaro.css`: every custom property they name would count as read. With the pack `editor-shiki`, name `editor/sebaro-shiki.json` too (its colours are custom properties).
- **Output:** one file, `tokens.css` and then `css/sebaro.css`, to load in place of both. Without comments, not minified: the site's bundler does that. The same input gives the same bytes; write it where the bundler reads it, never into a built folder after the build.
- **Kept as written:** every selector that stays is the stylesheet's own text, and the rules keep their order. A selector stays when every class, element and attribute outside `:not()` and `:has()` is used, and of each `:is()` or `:where()` list at least one entry. So it keeps the states of every part that stays (`:hover`, `:focus-visible`, `:target`, `[aria-…]`) and each of its forms in `@media print`, `forced-colors`, `@container` and `@supports`. The static state classes `.is-hover`, `.is-focus`, `.is-pressed`, `.is-visited`, `.is-active` and `.is-target` draw a state on a specimen page; no script of this folder sets them and a product does not, so a rule with one stays only where a page names that class.
- **Never cut:** `@keyframes` (four small ones), and no at-rule as a whole. `@font-face` stands in `fonts/fonts.css`, which is not an input: load it as it is.
- **Custom properties** are cut too: one stays when a rule that stays reads it, through other custom properties as well, when a file of the site names it, when `icons/sprite.css` of this folder reads it, or when a script of the copy reads it. A value set from JavaScript by a name the site's files do not hold (`"--sb-" + name`) is not seen: write the name out. A site that loads `tokens.tailwind.css` names it among its CSS files; it reads nearly every token.
- **A check to keep:** `product/` and `checks/` do not check the cut. After a change of the pages, compare a few of them in a browser with the whole stylesheet, in light and dark, also after the scripts ran. `checks/sb-colour-count.js` resolves every colour token: run it on a page with the whole `tokens.css`.

**The icon sprite.** `icons/sprite.svg` inlined as it is costs 56,773 bytes on every page. A site with a budget inlines only the symbols its pages use. Save this as `cut-icons.mjs` (Node 20+, built-ins only):

```js
// cut-icons.mjs: icons/sprite.svg of the copy with the symbols the site's pages use, to inline in place of the whole.
//   node cut-icons.mjs <the sebaro copy> <output.svg> <pages and scripts: files or folders>…
import fs from "node:fs";
import path from "node:path";

const [copy, out, ...site] = process.argv.slice(2);
if (!site.length) {
  console.error("usage: node cut-icons.mjs <the sebaro copy> <output.svg> <pages and scripts: files or folders>…");
  process.exit(2);
}
const walk = (p) => (fs.statSync(p).isDirectory() ? fs.readdirSync(p).flatMap((n) => walk(path.join(p, n))) : [p]);
const text = (f) => fs.readFileSync(f, "utf8");
const files = site.flatMap(walk).filter((f) => path.resolve(f) !== path.resolve(out) && /\.(html?|[cm]?js|json)$/.test(f));
// A symbol stays when a page names it (href="#search"), when a script of the site holds its id as a word, or when a
// script of the copy can name it (css/runtime-names*.json, "icons").
const used = new Set();
for (const f of files) {
  for (const m of text(f).matchAll(/\.[cm]?js$/.test(f) ? /[A-Za-z0-9_-]+/g : /#([A-Za-z][\w-]*)/g)) used.add(m[1] ?? m[0]);
}
for (const n of fs.readdirSync(path.join(copy, "css")).filter((n) => /^runtime-names(\.[a-z0-9-]+)?\.json$/.test(n))) {
  for (const script of Object.values(JSON.parse(text(path.join(copy, "css", n))).scripts)) {
    for (const id of script.icons ?? []) used.add(id);
  }
}
const sprite = text(path.join(copy, "icons", "sprite.svg"));
let kept = 0;
const cut = sprite.replace(/<symbol id="([^"]+)".*?<\/symbol>\n?/gs, (symbol, id) => (used.has(id) ? (kept++, symbol) : ""));
if (!kept) throw new Error("no symbol of the sprite is named in " + site.join(", "));
fs.mkdirSync(path.dirname(path.resolve(out)), { recursive: true });
fs.writeFileSync(out, cut);
console.log(`${out}: ${Buffer.byteLength(cut)} of ${Buffer.byteLength(sprite)} bytes, ${kept} symbol(s)`);
```

```sh
node cut-icons.mjs sebaro build/sprite.svg dist
```

The output is the sprite with the symbols a page names (`<use href="#search"/>`), a script of the site holds as a word, or a script of the copy can name; inline it where the whole sprite stood. An id built from parts in the site's own script is not seen: write it out.

## Checks

### Colour count and view checks

`sbColourCount(view)` reads one view and returns an object; `pass` is true when everything below holds. What it reads from the markup:

| Attribute | What the check does with it |
|---|---|
| `data-sb-view="<name>"` | a view root. Every element inside belongs to the nearest one |
| `data-sb-primary-expected="0"` | on a view root without a primary action: `primary` must then be 0, else 1 (`expected`) |
| `data-sb-view-type="<key>"` | optional, beside `data-sb-view`: the kind of view, one of `entry`, `overview`, `list`, `detail`, `form`, `flow`, `tool`, `result`, `read`, `history`, `search`, `settings`, `about`, `state-empty`, `state-loading`, `state-error`, `state-permission`, `outside`, `account`, `import`, `help`. `viewTypeErrors` then lists `unknown` (no such key), `product-area` (a product area outside `entry`, `overview`, `detail`, `result`, `state-empty`), `primary` (a primary action in `detail`, `read`, `history`, `search`, `settings`, `about`) and `list` (a `list` view without `ul.sb-list`, `ol.sb-list` or `.sb-listbox[role="listbox"]`, or with cards, an app grid or `[data-sb-collection="grid"]`) |
| `data-sb-action-area="<name>"` | optional: marks a task area by hand. `outlinedAreas` counts the outlined actions (`.sb-secondary-action`, `.sb-theme-button`, `[data-sb-theme-button]`) per area: the nearest marked area, view, `header`, `section`, `.sb-site-header`, `.sb-section`, `.sb-card`, `.sb-list-row`, `.sb-top-bar`, `.sb-toolbar`, `.sb-dialog__actions` or window part. More than one in an area fails |
| `data-sb-dialog-cancel` | on the one cancel button in `.sb-dialog__actions`: it is not counted as an outlined action (the first marked one only; never guessed from its word) |
| `data-sb-web-app-head` | the head of a web app: a theme button inside it fails (`headerThemeButtons`); a website's header never carries the mark |
| `data-sb-product="<id>"` | on every `.sb-product-area`: `areaErrors` lists an area without it or without its colours (`unknown product`), more than one area or product in a view, a control or too small a text in an area, a wrong ground or text colour |
| `data-sb-colour-count="<name>"` | on a development page: the element the line of the view `<name>` is written into |

The result: `{primary, place, status, signs, unknown, textOnColour, expected, productAreas, areaErrors, viewType, viewTypeErrors, framePrimary, outlinedAreas, headerThemeButtons, pass, line}`. `pass` asks for the expected number of primary-action fills, no colour without a role (`unknown` lists them), no text on a coloured fill, no area error, no view-type error, at most one primary action in an app frame, no theme button in a web app's head and at most one outlined action per area. Count each view in light and dark (`<html data-theme>`) and with the warm tone (`<html data-sb-tone="warm">`).

In CI (Playwright, after the page has loaded and its transitions have ended):

```js
await page.addScriptTag({ path: "<this folder>/checks/sb-colour-count.js" });
const views = await page.evaluate(() => [...document.querySelectorAll("[data-sb-view]")]
  .map((v) => ({ view: v.dataset.sbView, ...window.sbColourCount(v) })));
const failed = views.filter((v) => !v.pass);   // fail the run with failed.map((v) => v.line)
```

On a development page: `<script src="<this folder>/checks/sb-colour-count.js"></script>` at the end of the body writes each view's line („Farbprüfung: Hauptaktion 1 · … · bestanden“) into `[data-sb-colour-count="<name>"]` and counts again after `sb-theme-change`. The line is German only (a check, not UI text). Not read: pseudo-element paints (checkbox marks, chip frames, slider handles) and focus outlines.

## Product files

`product/` is the product kit. With this folder and its own declaration, `sebaro.product.json`, a product makes its own files and checks them in CI. `product/PRODUCT-CONTRACT.md` describes the declaration (its schema is `product/product.schema.json`), every output and the two records.

```sh
python3 <this folder>/product/product_kit.py build sebaro.product.json --copy <this folder> --out sebaro-product --render
python3 <this folder>/product/product_kit.py check sebaro.product.json --copy <this folder> --out sebaro-product    # CI
```

`build` writes into `sebaro-product/`, a folder of the product **outside this one**, and nothing here (Python 3.10+, standard library). `--render` then draws the PNG and ICO files with `product/render.mjs`: Node 20+ and the product's own Playwright with Chromium (`npm install --save-dev playwright`, then `npx playwright install --only-shell chromium`). A product without a Node project names a folder that holds `node_modules/playwright` in the environment variable `SEBARO_PLAYWRIGHT` (any folder in which `npm install playwright` ran; `build --render` passes it on). Without the flag the build names the files that wait, and `node <this folder>/product/render.mjs sebaro-product` draws them later. `check` writes nothing and needs Python alone: exit 1 with one line per output that is missing, edited or stale. It compares the declaration by what it says, so a formatter may change its white space and the order of its keys; it compares a raster file by sha256 with the renderer's record (`sebaro-product-raster.json`) and with the SVG under `render/` it was drawn from, never by pixel. A product that keeps no raster file adds `--no-raster` (an Android app whose Play icon and feature graphic are not in its repository).

**The product's scope.** `sign/product.css` holds one rule, `[data-sb-product="<id>"]`, which sets `--sb-product-tile` and `--sb-product-glyph` to the colours of the product's tile group. ## Keep in sync

A release of the sebaro design system is published as public copies, one archive per profile with every pack. `checks/update-copy.mjs` fetches the archive of this profile and writes this folder anew with the packs it should hold (Node 20+, built-ins only):

```sh
node <this folder>/checks/update-copy.mjs --check                 # changes nothing; exit 1 when a newer release exists (a scheduled CI job)
node <this folder>/checks/update-copy.mjs                         # the newest release, with the profile and the packs of this copy
node <this folder>/checks/update-copy.mjs --packs <pack>,<pack>   # the same with another choice of packs
node <this folder>/checks/update-copy.mjs --release <tag>         # one release, not the newest
```

**What changed for a product** is in `CHANGES.md` of this folder: one section per release, in plain sentences, with what to do after the update. After an update the updater prints the sections between the release this copy had and the new one; `--check` prints their headings when a newer release exists.

It reads `copies.json`, `CHANGES.md` and `sebaro-desktop.tar.gz` from `https://github.com/grundhofer/sebaro-blueprint/releases` (`/latest/download/<file>`; with `--release <tag>`, `/download/<tag>/<file>`; another place with `--from <folder or URL>` or the environment variable `SEBARO_COPIES`). It checks the sha256 of the archive against the index and of every file against the release's record, writes the copy into a temporary folder beside this one and swaps the two at the end, so a failed run leaves this folder as it was. It refuses while a file here is edited, added or missing, the test of `checks/verify-export.mjs --strict` (`--force` writes anyway); a dotfile and, with `--force`, a file the record does not name stay. Exit 0 written, or with `--check` at the newest release · 1 `--check`: a newer release exists, both versions are printed · 2 usage: an unknown option, profile or pack, a pack without the pack it needs (the message lists what exists) · 3 refused: local changes · 4 the release cannot be read or does not verify; nothing was changed.

The files it writes are byte for byte the files of that release for this profile and these packs. `sebaro-export.json` records the release (`release`: the tag, the archive and the updater) and the day the copy was written, and measures the stylesheets where it was written (`cssSizes`). The first copy of a product comes from the same file, fetched alone from the release: `node update-copy.mjs --profile desktop [--packs <pack>,<pack>] --out <folder>`.

### In the product's CI

This folder brings its own checks; the section *What needs what* says what each needs. These belong to every build:

```sh
node <this folder>/checks/verify-export.mjs --strict    # this folder is unchanged
python3 <this folder>/product/product_kit.py check sebaro.product.json --copy <this folder> --out sebaro-product    # the product's files are what its declaration gives
sh <this folder>/checks/lint-web.sh <the product's CSS source files> <the folder of its .html pages>    # the product's sources keep the rules
```

The question for a newer release belongs to a scheduled job once a week, not to every build: it turns red on the day of a release, whatever the product changed. In GitHub Actions: `schedule` with a `cron` line beside `push` and `pull_request`, and this step only `if: github.event_name == 'schedule'`.

```sh
node <this folder>/checks/update-copy.mjs --check    # a newer release exists: exit 1; update with checks/update-copy.mjs, as a commit of its own
```

Keep this folder and the product's folder (`sebaro-product/`) out of the product's formatter and linter, and out of any commit hook that formats: a reformatted file here is an edited copy, one there a stale product file, and the checks above fail on both.

`checks/verify-export.mjs` checks this folder (or the export folder given as its argument) against `sebaro-export.json`: every recorded file present and unchanged. One line per finding (`FAIL  missing in target: …`, `FAIL  edited in target: …`, `WARN  not part of the export: …`) and a summary line. Exit 0 no errors, 1 a missing or edited file (with `--strict` also a file the record does not name, without it a warning), 2 usage error or a missing or unreadable `sebaro-export.json`. `--strict` never counts `sebaro-export.json` itself, dotfiles or anything in a dot folder; anything else the product puts into this folder fails it, so keep the product's own files outside. It does not look for a newer release: `checks/update-copy.mjs --check` does.

`checks/update-copy.mjs` holds a call of `fetch(`. Where this folder lies inside an app's source tree and the product checks its UI sources for network calls, leave this folder's `checks/` out of that check: nothing in `checks/` or `product/` is loaded by the app.

`checks/lint-web.sh` is the lint of the system's rules for the CSS a product writes and for its pages (8 rules, L1-L8, counted from the ids its lines carry):

```sh
sh <this folder>/checks/lint-web.sh <css file>... <page dir>
```

Name every CSS **source file** of the product, then the folder of its pages, which is searched with its subfolders for `.html`. **Source files, not the built bundle**: the rules read a stylesheet line by line and take a rule's selector from the line with its `{`. A minified bundle is one line and one selector to them, so they tell nothing about it, and the token values in it fail `L5`. One line per finding, `<rule> <file>:<line>: <text>`. Exit 1 on a finding; exit 2 with a usage line when an argument is missing, a CSS file does not exist or the folder holds no `.html`. **A clean run prints nothing: silence with exit 0 is success.**

| Rule | What it asks |
|---|---|
| `L1` | `--sb-color-primary-action*` and `--sb-color-on-primary-action` only in rules whose selector contains `.sb-primary-action` |
| `L2` | no `--sb-color-{accent,success,warning,danger,info}-subtle` and no `--sb-color-text-on-*` anywhere (no tinted areas); the one exception: `success-subtle` / `danger-subtle` in rules whose selector names `.sb-diff__line--add` / `--del` (D85, spec/02 §3.19) |
| `L3` | no `data-product` in CSS or on any page element; generated fixed-pair tiles use inert `data-sb-product` (D40; §4.6) |
| `L4` | `background` with `accent`, `link`, `success`, `warning`, `danger` or `info` only in `.sb-switch`, `.sb-radio`, `.sb-range` rules (indicator fills without text). The lint reads the property, not the size of the box: a place line is a border, as `css/sebaro.css` draws it (`border-inline-start: var(--sb-border-width-strong) solid var(--sb-color-accent)`), and a 3 px box with an accent `background` is reported |
| `L5` | no hex, `rgb(`, `hsl(` or named colours in `css/sebaro.css` (only `var(--sb-*)`, `var(--sb-x-sebaro-*)`) |
| `L6` | no remote URL in CSS or pages (`https?://` outside `href` of real links) |
| `L7` | the notes list is never laid out in columns: no `columns`, no multi-column `grid-template-columns` on `.sb-notes__list` |
| `L8` | a control size token (`--sb-size-control-*`, px) is only ever a minimum: no `height` or `block-size` from it in CSS or a page's `style`, also not inside `calc()` or `min()`, so a box with text grows at 200 % instead of cutting it (a `max()` of the token and a line height in `lh` or `em`, such as `max(var(--sb-size-control-sm), 1lh)`, is a minimum and allowed); boxes without text (an icon button, a tree twist, a chart's SVG bar) are exempt when every selector of the rule ends in such a box (`svg`, `.sb-icon-button…`, `…__twist`) |

The script holds the shell part of each rule: what a row says beyond a pattern in a file (a named colour, a remote URL in a page) is a review.
